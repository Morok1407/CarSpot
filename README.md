# CarSpot

Десктоп-приложение: React + TypeScript, Tauri 2, Rust и MongoDB.
Реализованы CRUD мест, интерфейс оператора, приём автомобиля, время стоянки,
почасовые тарифы, отметка оплаты наличными/картой и оформление выезда.
Добавлена страница аналитики с графиками. Платёжный эквайринг, печать талонов,
экспорт отчётов не реализованы. История завершённых стоянок хранится отдельно.

## Интерфейс оператора

- **Обзор** — общая вместимость, свободные и занятые места, обслуживание,
  загрузка парковки и последние обновлённые записи (не журнал въездов).
- **Парковка** — единый раздел с переключателем «Схема / Список».
  На схеме места сгруппированы по типу транспорта; расположение схематичное.
  Нажатие на место открывает его карточку. Поиск по номеру места/госномеру
  и фильтры работают в обоих представлениях и охватывают все страницы API.
- **Добавить место / Редактировать** — формы сохраняют данные в MongoDB.
- **Принять автомобиль** — выбрать свободное место, госномер, время въезда,
  режим тарифа и цену часа в целых тенге (начальное значение формы — 500 ₸/ч,
  его можно изменить). Приём с карточки сразу выбирает конкретное место.
- **По времени** — оператор задаёт планируемый выезд; стоимость выбранного
  периода фиксирована. Неполный час округляется вверх. Допускается оплата
  заранее; перерасчёта при раннем/позднем выезде в этом режиме нет.
- **Открытый тариф** — планируемый выезд не задаётся. При оплате оператор
  указывает фактический выезд (по умолчанию текущее время), сумма считается
  по фактической длительности с округлением неполного часа вверх.
- **Изменить время и тариф** — изменить условия активной стоянки до оплаты.
- **Оплатить** — выбрать наличные, карту или смешанную оплату и отметить полученную оплату.
  Сумма пересчитывается и проверяется Rust; деньги не списываются. Повторная
  оплата и изменение оплаченных условий блокируются.
- **Оформить выезд** — после оплаты освободить место с подтверждением.
  Для открытого тарифа сохраняется время выезда, выбранное при оплате;
  для режима по времени — текущее время оформления выезда.
- В пустой базе доступно создание стандартного набора из 50 мест.

Актуальные данные загружаются при открытии приложения и кнопкой обновления
на схеме/в списке. После сохранения карточки локальный список обновляется.
При ошибке подключения последняя загруженная информация остаётся видимой,
изменения блокируются до успешного обновления. В обычном браузере отображается
подсказка о запуске через Tauri; демонстрационные данные не подставляются.

В `parking_spots` хранится только состояние места и активная стоянка
(`active_visit`). Завершённые визиты сохраняются в `completed_visits`:
госномер, время, тариф, платёж с распределением наличных/карты и снимок номера
и типа места. Все визиты сохраняются, в том числе после удаления места.
Раздел **Обслуженные авто** показывает историю с поиском и разбивкой на страницы.

Обычный локальный MongoDB без replica set поддерживается: сначала идемпотентно
сохраняется история по уникальному ID визита, затем освобождается место с
проверкой того же ID. При сбое между этими действиями место остаётся занятым;
повторный выезд или перезапуск приложения завершает освобождение без дубликата.
При первом подключении старые `last_visit` переносятся в историю и удаляются
из документов мест только после успешного сохранения. Перенос повторяемый.
Ранее перезаписанные или удалённые визиты восстановить невозможно.

## Аналитика

Раздел **«Аналитика»** в боковом меню показывает:

- динамику суммы сохранённых оплат по дням за 7, 30 или 90 дней;
- доли наличных и карты от суммы оплат, количество оплат каждым способом;
- текущую загрузку парковки и состояния всех мест;
- распределение свободных, занятых и обслуживаемых мест по типу транспорта;
- сумму и количество сохранённых оплат, среднюю оплату и среднюю длительность
  завершённых сохранённых визитов.

Период включает сегодняшний день и предыдущие дни по местному времени.
Оплаты отбираются по дате отметки оплаты, длительность — по дате завершения
визита. Текущая загрузка не зависит от периода. Повторные идентификаторы визитов
не считаются дважды. Для отсутствующих средних показателей отображается «—».
Точки графика доступны мышью и клавиатурой; под графиком есть таблица по дням.
Кнопка «Обновить данные» загружает свежий снимок из MongoDB.

Аналитика объединяет `completed_visits` и оплаченные активные стоянки.
Завершение следующего визита и удаление места больше не сокращают историю.
Старые данные учитываются в объёме, сохранившемся к моменту миграции.

## Подключение и запуск

Нужен работающий **MongoDB Server**. Compass — клиент для просмотра этой же базы.
По умолчанию Rust подключается к `mongodb://127.0.0.1:27017`, база `CarSpot`,
коллекции `parking_spots` и `completed_visits`. В Compass используйте этот адрес и обновите список баз.

```powershell
npm run db:seed
npm run tauri dev
```

`db:seed` создаёт 50 свободных мест: `A-001`–`A-040` для легковых автомобилей,
`M-001`–`M-005` для мотоциклов, `T-001`–`T-005` для грузовиков.
Используется `$setOnInsert`: существующие записи не перезаписываются. Повторный
запуск добавляет только отсутствующие номера, в том числе ранее удалённые.
При обычном запуске приложения заполнение автоматически не выполняется.

Для другого подключения задайте переменные в терминале перед запуском:

```powershell
$env:MONGODB_URI = 'mongodb://127.0.0.1:27017'
$env:MONGODB_DATABASE = 'CarSpot'
```

`.env` автоматически не читается. URI хранится только на стороне Rust;
не помещайте учётные данные в переменные `VITE_*` или исходники React.
Подключение ленивое, общее для команд. После неудачного подключения следующий
вызов повторяет попытку. При недоступности сервера возвращается ошибка `database`.

Если команда `npm` сообщает, что не найден `npm-cli.js` в AppData, можно
использовать установленный npm напрямую:

```powershell
& 'C:/Program Files/nodejs/npm.cmd' run db:seed
& 'C:/Program Files/nodejs/npm.cmd' run tauri dev
```

## API для React

Типизированные функции находятся в `src/api/parking.ts` и используют Tauri IPC,
а не HTTP. Они работают в десктоп-приложении; одного `npm run dev` недостаточно.

```typescript
import { parkingApi } from './api/parking';

const created = await parkingApi.create({
  number: 'A-041',
  vehicle_type: 'car', // car | motorcycle | truck
  status: 'available', // available | occupied | maintenance
  license_plate: null,
});
const page = await parkingApi.list(null, 0, 100);
const free = await parkingApi.list('available');
const spot = await parkingApi.get(created.id);
await parkingApi.update(spot.id, {
  number: spot.number,
  vehicle_type: spot.vehicle_type,
  status: 'occupied',
  license_plate: '123ABC01',
});
// Перед удалением освободить место:
await parkingApi.update(spot.id, {
  number: spot.number,
  vehicle_type: spot.vehicle_type,
  status: 'available',
  license_plate: null,
});
await parkingApi.delete(spot.id);
```

Команды: `list_parking_spots`, `get_parking_spot`, `create_parking_spot`,
`update_parking_spot`, `delete_parking_spot`, `seed_parking_spots`.
Обновление принимает все поля `SpotInput`; `id` передаётся отдельно.
Список сортируется по номеру, поддерживает фильтр состояния, смещение и размер
страницы 1–200 (по умолчанию 100). Идентификаторы в API — строки ObjectId,
временные отметки — миллисекунды Unix; в MongoDB хранятся BSON ObjectId и Date.

Номера обрезаются по краям и приводятся к верхнему регистру. Номер места
уникален; один госномер может занимать только одно место. Для занятого места
госномер обязателен, для остальных состояний должен быть `null`.
Занятые места защищены от удаления атомарным фильтром MongoDB.
Ошибки отклоняют Promise объектом `{ code, message }`: `validation`,
`not_found`, `conflict`, `configuration`, `database`.

Это административный CRUD: при одновременном редактировании параметров места
сохраняется последнее обновление. Места с активной стоянкой нельзя менять через
общий `update`; для них используются отдельные операции:

```typescript
const admitted = await parkingApi.admit(spot.id, {
  license_plate: '123ABC01',
  entry_at_ms: Date.now(),
  tariff_mode: 'open', // planned — указать planned_exit_at_ms
  planned_exit_at_ms: null,
  hourly_rate: 500,
});
// Позже, при выезде:
const visit = admitted.active_visit!;
const departure = Date.now();
const expected = Math.ceil((departure - visit.entry_at_ms) / 3_600_000) * visit.hourly_rate;
await parkingApi.pay(spot.id, visit.id, departure, 'cash', expected);
await parkingApi.checkout(spot.id, visit.id);
```

Команды Tauri: `admit_vehicle`, `revise_visit`, `pay_visit`, `checkout_vehicle`.
После приёма автомобиля по тарифу с заданным временем автоматически открывается
окно оплаты. Закрытие окна оставляет стоянку неоплаченной; оплатить можно позже
из карточки. Для открытого тарифа оплата выполняется при выезде.

В смешанной оплате оператор указывает суммы наличными и картой отдельно.
По умолчанию сумма делится поровну; кнопка «Разделить поровну» восстанавливает
это распределение. Обе суммы должны быть положительными целыми числами,
а их сумма — совпадать со стоимостью. Проверка выполняется также сервером.
Например, при стоимости 1000 ₸:

```typescript
await parkingApi.pay(spot.id, visit.id, departure, 'mixed', 1000, {
  cash_amount: 300,
  card_amount: 700,
});
```

Распределение сохраняется в платеже и отображается в карточке стоянки.
В аналитике смешанные платежи представлены отдельной категорией полной суммой,
без двойного учёта.

Все денежные суммы — целые тенге; интервалы должны быть положительными и
не превышать 366 дней. Въезд/фактический выезд не допускаются в будущем.
Официальная документация драйвера: https://www.mongodb.com/docs/drivers/rust/current/.

## Демонстрационные данные

При запущенной локальной MongoDB выполните `npm run db:demo`, затем обновите
данные приложения. Используются настройки `MONGODB_URI` и `MONGODB_DATABASE`.
Скрипт добавляет 60 мест с префиксом `DEMO-`, 84 стоянки и 72 платежа за разные
даты для демонстрации аналитики, включая наличные, карту и смешанную оплату.
Существующие записи не изменяются; повторный запуск не создаёт дубликаты
и не обновляет даты уже созданных демонстрационных записей.

## Проверки

```powershell
npm run build
npm run test:analytics
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo test --manifest-path src-tauri/Cargo.toml --lib -- --ignored
```

Последняя команда требует MongoDB. Она создаёт отдельную базу
`carspot_test_<ObjectId>`, проверяет CRUD, индексы, защиту занятого места и
повторное заполнение, затем удаляет только эту тестовую базу. Рабочая база
не затрагивается. При аварийном завершении тестовая база может остаться.

`test:analytics` требует Node.js 22.6+ (проверено на 22.16), запускает
тесты агрегирования без MongoDB: границы периода, пустые данные, повторяющиеся
визиты, даты оплат и завершения, неизменность текущей загрузки при смене периода.
